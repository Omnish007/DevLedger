## Data and form boundary catalogue

Apply these cases to each field/API where its actual schema allows them; do not impose generic expectations on fields that intentionally accept empty values.

- Required values: missing, whitespace-only, trim normalization, valid minimum, just-over-maximum.
- Text: Unicode scripts, emoji, combining marks, RTL characters, punctuation, quotes, literal HTML/script-like text, newlines, tabs, long values.
- Identifiers: malformed UUID/string, nonexistent id, soft-deleted id, id belonging to another project.
- Dates: blank when optional, malformed, ambiguous, leap day, daylight-saving boundary, past/future, timezone transition, invalid local datetime.
- Numeric values: zero, negative, minimum, maximum, maximum plus one, decimals where integers are expected.
- Repeated actions: double submit, rapid create/delete, navigation during save, repeated timer start, concurrent mutation requests.
- Persistence: write error, busy DB, app restart immediately after mutation, reload during save, incomplete file copy.
- Search: empty, one-character, partial, exact, case variation, leading/trailing whitespace, punctuation, Unicode, no result, large query, post-update and post-delete index state.

## Security input catalogue

Use inert test strings such as `<script>window.__test = true</script>`, quotes, path traversal-looking text (`../outside.txt`) and invalid IPC payload shapes. Assert these are treated as text or rejected by validators; never execute the content, access files outside the isolated profile, disable Electron security settings, or invoke shell commands from renderer-controlled strings.
